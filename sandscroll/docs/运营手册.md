## 2. 开播清单（首次约 2 小时 + YouTube 最长 24 小时审核）

### 2.1 YouTube 频道（负责人）

1. 用品牌账号创建频道（便于多人协作管理），完成**手机号验证**。
2. YouTube Studio → 创建 → **进行直播**。首次开通直播最长需要 **24 小时**生效，请尽早申请。
3. 直播 → **串流** 标签页：
   - 选择「**默认串流密钥**」（可重复使用，服务器长期推流用它）。
   - 复制**串流密钥**（等同密码，只放进服务器的 `deploy/.env`，不要发群、不要提交代码库）。
   - 延迟选「**正常延迟**」（画质最好）；开启 **DVR**。
   - 关闭「**自动停止**」，这样短暂断线重连后仍是同一场直播。
4. 受众设置：「**否，不是面向儿童的内容**」（面向儿童会关闭聊天等功能）。
5. 类别：**音乐**；语言：中文，另添加英文标题/描述翻译。

### 2.2 服务器（技术值守）

**配置要求**：4 vCPU（x86）、8 GB 内存、Ubuntu 22.04/24.04、**每月外网流量 ≥ 3 TB**（7 Mbps × 24 小时 × 30 天 ≈ 2.3 TB）。
实测：在 4 核机器上，1080p30 渲染 + x264 编码速度约为实时的 **2.3 倍**，余量充足；2 核机器请改用 720p。

**地域**：选择可稳定访问 YouTube 的海外区域（香港、新加坡、东京、美国西部均可）。YouTube 在中国大陆无法直接访问，请在合规前提下由海外服务器推流，并遵守所在机构的对外发布规定。

```bash
# 1) 安装 Docker（官方脚本）
curl -fsSL https://get.docker.com | sh

# 2) 获取代码
git clone https://github.com/MbappeWU/Project-Test.git
cd Project-Test/sandscroll

# 3) 填写推流密钥
cp deploy/.env.example deploy/.env
nano deploy/.env        # 把 YOUTUBE_STREAM_KEY 换成真实密钥

# 4) 启动（后台常驻，崩溃或重启服务器后自动恢复）
docker compose up -d --build

# 5) 看日志：应每分钟出现一行 t=… speed=1.00x
docker compose logs -f --tail=50
```

约 30 秒后，YouTube Studio 的直播控制台会显示「**良好**」并出现画面，点击「**开始直播**」（若开启了自动开始则无需操作）。

### 2.3 上线前自检（5 分钟）

- [ ] 本地先渲染 1 分钟样片检查音画：`npm run render -- --duration 60s` → 生成 `preview.mp4`。
- [ ] 直播控制台「直播健康状况」无红色告警（码率、关键帧间隔 2 秒）。
- [ ] 手机上打开直播，确认中英文字幕清晰、音量适中（实测综合响度约 −15.5 LUFS，接近 YouTube 的 −14 LUFS 标准，平台不会大幅压缩音量）。
- [ ] 聊天室已开启审核（见第 4.3 节）。

## 4. 日常运营

### 4.1 每日巡检（10 分钟）

| 检查项 | 位置 | 正常标准 |
|---|---|---|
| 直播是否在线、画面是否在动 | 频道主页 / 手机 | 画面在绘制或停留在字幕页 |
| 直播健康状况 | Studio 直播控制台 | 「良好」或「极佳」 |
| 容器状态 | `docker compose ps` | `healthy` |
| 日志速度 | `docker compose logs --tail=5` | `speed=1.00x`，无持续 reconnect |
| 聊天室 | Studio | 无待处理的违规留言 |

### 4.2 每周更新（1 小时）

1. **时事字幕**：编辑 `program.json` 的 `notes`（如大熊猫抵达后，把“即将落户”改为“已落户”；节日后删除中秋字幕），然后 `docker compose restart`。改动前由内容审核核对事实。
2. **节目单**：调整 `program` 顺序或删减场景（如只播常青内容）。
3. **数据复盘**：见第 6 节。
4. **Shorts**：从直播中剪 30–60 秒的「一幅画从无到有」片段，每周 3–5 条，是新频道最有效的引流方式。可用 `node src/node/stream.mjs --out pandas.mp4 --duration 150s --program pandas` 直接渲染单幅高清素材。

### 4.3 聊天室与社区

- 开启「**暂停可能不当的消息以待审核**」、**慢速模式**（10–30 秒）、屏蔽词列表（政治攻击、辱骂、广告链接）。
- 指定 1–2 名管理员；置顶一条欢迎语：「欢迎来到《山海不为远》，愿你在沙与琴声中得片刻安宁。」
- 话题出现争执时，只回应艺术与文化内容，不参与政治辩论。

### 4.4 故障处理

| 现象 | 处理 |
|---|---|
| 直播中断、Studio 显示「未收到数据」 | `docker compose logs --tail=50` 看报错；程序会自动重连（2 秒起、最长 60 秒退避）。连续失败检查密钥与服务器网络 |
| 画面卡顿、健康状况提示码率低 | 日志里 `speed` 低于 1.00x 表示 CPU 不足：升级到 4 核以上，或在 `.env` 改为 720p（1280×720、4000k） |
| 字幕内容需要紧急撤下 | 在 `program.json` 把该场景的 note 设为 `null`，`docker compose restart` |
| 需要停播 | `docker compose down`（10 秒内安全退出） |
| 更新到新版本 | `git pull && docker compose up -d --build` |

复盘节奏：每周看「观看时长来源」（搜索、推荐、Shorts、外部），把资源投向增长最快的渠道。

**变现门槛（参考）**：YouTube 合作伙伴计划通常要求 1,000 订阅 + 近 12 个月 4,000 小时公开观看时长（或 Shorts 1,000 万次观看／90 天）。注意 YouTube 对「批量生产、重复性内容」（2025 年起称 *inauthentic content*）不予变现：保持人工策划、定期更新场景与节目说明、在描述中说明创作理念，可以降低被判定为重复内容的风险。

## 7. 合规与风险

| 风险 | 说明 | 措施 |
|---|---|---|
| 音乐版权（Content ID） | 商业录音的古典音乐常被版权方认领 | 本项目音乐由程序实时原创，不含任何录音或现成编曲 |
| 字体与文本 | 字体许可、诗词引用 | 字体均为 SIL OFL；古诗词属公有领域；费孝通「美美与共」为十六字短句引用，并署名 |
| 政治敏感 | 以国家领导人出访为主题的内容易引发争议 | 以象征物表达（明月、长城、熊猫、桥），**不绘制领导人肖像**，不做口号式表达；时事字幕只写可核实的事实 |
| 冒用官方身份 | 容易被误认为官方媒体 | 频道名、描述中不使用官方机构名称或标识，明确「独立艺术创作」 |
| 领导人名义用于商业 | 若频道变现，使用领导人姓名或形象做推广存在合规风险（参见《广告法》相关规定） | 缩略图与广告素材不使用领导人姓名、形象；标题仅以「中美元首互访之际」等中性措辞交代背景 |
| 合成内容标注 | YouTube 要求对「可能被误认为真实」的合成内容进行标注 | 沙画为明显的艺术风格，一般无需标注；描述中主动说明「由程序生成」，保持透明 |
| 平台可达性 | 大陆无法直接访问 YouTube | 服务器部署在海外，运营人员遵守所在机构的跨境与对外发布规定 |
| 直播存档 | 超过 12 小时的直播不会完整存档 | 精彩片段以 Shorts 或单独视频形式另行发布 |
